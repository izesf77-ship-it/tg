# 👋 Конструктор переписок — Telegram-бот

Бот для создания **вымышленных** переписок в стиле популярных мессенджеров
и получения готового PNG-изображения прямо в Telegram.

Весь интерфейс работает **внутри Telegram** (сообщения, InlineKeyboard, ReplyKeyboard) —
без Mini Apps, веб-сайта и внешних страниц.

> ⚠️ **Назначение.** Проект создан для юмора, мемов, сценариев и контента.
> Пометку `FICTIONAL CHAT` можно включить в настройках переписки
> (по умолчанию она выключена).
> Бот **не предназначен** для подделки документов, банковских сообщений,
> фишинга, кражи аккаунтов или выдачи переписки как доказательства.

## 🎯 Возможности

### Создание переписки
- 5 стилей интерфейса: **Telegram**, **Dark Telegram**, **WhatsApp**,
  **Messenger**, **Простой чат**
- Настройка двух участников: имя, username, фото (загружается прямо из Telegram),
  статус, время последнего входа, Premium, отображаемое имя
- Автосохранение: переписка сохраняется после каждого действия,
  к `/start` можно вернуться и продолжить

### Редактор сообщений
- Текст, emoji, несколько сообщений подряд
- Фотографии (реальные, загруженные из Telegram)
- Голосовые, файлы, стикеры — как визуальные mock-элементы
- Ответы на сообщения, пересылки, реакции
- Галочки прочтения (одна / две / синие), время, разделители дат, системные сообщения
- Изменение текста, времени, автора, типа и реакции
- Перемещение вверх/вниз, удаление
- Время вручную в форматах `12:41`, `23:07`, `09:15`, `2307`, `9.15`

### Генерация изображения
- Автоматическая высота: 5 или 500 сообщений — картинка растёт сама
- Перенос длинных текстов, в том числе слов длиннее ширины пузыря
- Корректная отрисовка русского, английского, цифр и emoji
- Пометка `FICTIONAL CHAT` / `ВЫМЫШЛЕННАЯ ПЕРЕПИСКА` — **выключена по умолчанию**, включается в настройках переписки

### Дополнительно
- **10 готовых шаблонов**: ревность, неожиданное сообщение, бывшие,
  дружеский прикол, розыгрыш, знакомство, рабочая переписка,
  странное сообщение, переписка с незнакомым, мемная переписка
- **AI-сценарии** через OpenRouter (отключаются, если нет ключа)
- **Админ-панель**: статистика, пользователи, рассылка с подтверждением, лимиты
- **Лимиты** и защита от спама с хранением в SQLite
- **Premium** подготовлен (включая заготовку под Telegram Stars)

## 2. Создание бота через BotFather

1. Откройте Telegram и найдите **@BotFather**
2. Отправьте `/newbot`
3. Введите имя бота: `Конструктор переписок`
4. Введите username: `my_chat_constructor_bot` (должен заканчиваться на `bot`)
5. BotFather выдаст **токен** вида:
   ```
   7123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw
   ```
6. **Сохраните токен** — он понадобится в `.env`

Полезные команды BotFather:
- `/setdescription` — описание бота
- `/setabouttext` — текст «О боте»
- `/setuserpic` — аватар бота

## 3. Настройка `.env`

Скопируйте пример в рабочий файл:

**Windows (PowerShell):**
```powershell
Copy-Item .env.example .env
```

**Linux / macOS:**
```bash
cp .env.example .env
```

Минимально нужно заполнить **два** поля:

```ini
BOT_TOKEN=7123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw
ADMIN_IDS=712345678
```

Где `ADMIN_IDS` — ваш Telegram ID. Узнать его можно:
- через [@userinfobot](https://t.me/userinfobot)
- или через бота [@getmyid_bot](https://t.me/getmyid_bot)

Несколько админов — через запятую: `ADMIN_IDS=111111,222222,333333`

Полный пример `.env`:

```ini
# --- Обязательное ---
BOT_TOKEN=7123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw
ADMIN_IDS=712345678

# --- База данных ---
DB_PATH=data/bot.sqlite3

# --- AI (необязательно; без ключа функция отключается) ---
OPENROUTER_API_KEY=
OPENROUTER_MODEL=openai/gpt-4o-mini
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1/chat/completions

# --- Сеть (если хостинг не пускает к api.telegram.org) ---
# TELEGRAM_PROXY=socks5://user:password@host:1080
TELEGRAM_PROXY=

# --- Лимиты ---
LIMITS_IMAGE_PER_HOUR=20
LIMITS_AI_PER_HOUR=5
LIMITS_IMAGE_PER_HOUR_PREMIUM=100
LIMITS_AI_PER_HOUR_PREMIUM=30
LIMITS_ACTIONS_PER_MINUTE=60
LIMITS_MAX_MESSAGES=200
LIMITS_MAX_CHATS=100

# --- Монетизация (заготовка под Telegram Stars) ---
PREMIUM_ENABLED=false
PREMIUM_STARS_PRICE=250

# --- Рендерер ---
FONTS_DIR=fonts
RENDER_WIDTH=1080
RENDER_MAX_HEIGHT=20000

# --- Логи ---
LOG_LEVEL=INFO
LOG_FILE=

# --- Прочее ---
AD_TEXT=⭐️ Premium: безлимитные генерации, больше стилей и AI-сценарии.
```

## 5. Настройка шрифтов (важно)

Рендерер ищет шрифты сначала в папке `fonts/`, затем в системных каталогах.
Кириллица проверяется автоматически — шрифты без русских букв пропускаются.

**Подробная инструкция и список файлов — в [`fonts/README.txt`](fonts/README.txt).**

Кратко:

1. Положите в `fonts/` основной шрифт с поддержкой кириллицы:
   - `Inter-Regular.ttf` (рекомендуется) — https://rsms.me/inter/
   - или `Roboto-Regular.ttf`, `NotoSans-Regular.ttf`, `OpenSans-Regular.ttf`
2. Для красивых emoji добавьте:
   - `NotoColorEmoji.ttf` — https://fonts.google.com/noto/specimen/Noto+Color+Emoji
3. Проверьте установку:
   ```bash
   python check.py
   ```

В отчёте должно быть:
```
[OK] Эмодзи и кириллица в тексте — шрифты: {'text_font': 'Inter-Regular.ttf', 'emoji_font': 'NotoColorEmoji.ttf', 'emoji_color': 'да'}
```

Если `text_font` = `встроенный Pillow` — шрифты не найдены, русский текст будет нечитаемым.

Быстрая установка emoji-шрифта на Linux:
```bash
sudo apt install -y fonts-noto-color-emoji fonts-dejavu-core
```

## 6. Запуск

```bash
python -m bot.main
```

или

```bash
python -m bot
```

Если `bot/__main__.py` отсутствует, используйте первую команду.

Ожидаемый вывод:

```
==============================================================
  Telegram Chat Constructor Bot запущен
  AI: AI выключен: не задан OPENROUTER_API_KEY
  Администраторы: 1
  БД: C:\...\data\bot.sqlite3
==============================================================
  Шрифты: {'text_font': 'Inter-Regular.ttf', ...}
  Поллинг запущен. Нажмите Ctrl+C для остановки.
```

Откройте бота в Telegram и нажмите **Start**.

### Перед запуском — самопроверка

```bash
python check.py
```

Скрипт проверит импорты, Dispatcher, клавиатуры, схемы, лимиты, рендер всех
стилей, кириллицу, emoji, длинные тексты, 60 сообщений, битые файлы,
шаблоны и полный сценарий работы с SQLite. Тестовые изображения
сохраняются в `output/`, отчёт — в `_check_report.txt`.

### Unit-тесты

Автоматические тесты проверяют валидацию текста и времени, callback-вход
в создание, права администратора, SQLite cascade, лимиты, emoji/wrapping
и рендер переписок разного размера:

```bash
python -m unittest discover -s tests -v
```

sudo apt update

# 4. Конфигурация
cp .env.example .env
nano .env

# 5. Проверка
python check.py

# 6. Запуск
python -m bot.main
```

**systemd-сервис (рекомендуется для VPS):**

Создайте `/etc/systemd/system/chatbot.service`:

```ini
[Unit]
Description=Telegram Chat Constructor Bot
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/chat-constructor-bot
ExecStart=/opt/chat-constructor-bot/.venv/bin/python -m bot.main
Restart=always
RestartSec=10
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

Запуск:

```bash
sudo systemctl daemon-reload
sudo systemctl enable chatbot
sudo systemctl start chatbot
sudo systemctl status chatbot

# Логи в реальном времени
sudo journalctl -u chatbot -f
```

**Быстрый запуск через screen/tmux:**

```bash
sudo apt install -y tmux
tmux new -s bot
source .venv/bin/activate && python -m bot.main
# Отключиться: Ctrl+B, затем D
# Вернуться: tmux attach -t bot
```

## 🐳 Запуск в Docker (для хостингов и панелей)

Проект полностью готов к сборке в контейнере. Подходит для панелей
хостинга, которые умеют собирать образ из репозитория.

### Что добавлено

| Файл | Назначение |
|------|------------|
| `Dockerfile` | Двухстадийная сборка: builder → runtime |
| `.dockerignore` | Исключает `.env`, `data/`, кэши, шрифты пользователя |
| `docker-compose.yml` | Сервис, volume, healthcheck, restart-политика |
| `docker-entrypoint.py` | Проверяет токен/шрифты/БД и запускает бота |
| `check_docker.py` | Проверка конфигурации без Docker (42 проверки) |

### Особенности образа

- **Две стадии** — компилятор (`build-essential`) остаётся только в стадии сборки
- **Шрифты уже внутри** — `fonts-dejavu-core`, `fonts-noto-core`, `fonts-noto-color-emoji`.
  Кириллица и emoji работают сразу, ничего докачивать не нужно
- **Pillow** — установлены `libjpeg62-turbo`, `zlib1g`, `libfreetype6`
- **Непривилегированный пользователь** `appuser`
- **Volume `/app/data`** — БД и фото переживают пересборку
- **Healthcheck** и `restart: unless-stopped`
- **Размер образа** ~350 МБ
- **Порты не нужны** — бот работает через long polling

### Проверка конфигурации

```bash
python check_docker.py
```

### Локальный запуск

```bash
# Через Compose (рекомендуется)
cp .env.example .env      # вписать BOT_TOKEN и ADMIN_IDS
docker compose up -d
docker compose logs -f

```bash
# Через docker run
docker build -t chat-constructor-bot .

### Деплой на хостинг (панель типа relaxdev.ru)

1. **Загрузите проект в Git-репозиторий** (GitHub / GitLab).
   Убедитесь, что `.env` **не** попал в репозиторий — он в `.gitignore`.

2. **В панели хостинга** создайте приложение:
   - Тип: **Docker**
   - Репозиторий: ваш Git
   - Ветка: `main`
   - Dockerfile: `/Dockerfile` (путь по умолчанию)
   - Контекст сборки: `/` (корень репозитория)

3. **Задайте переменные окружения** в панели (или в `.env` рядом с проектом):

4. **Подключите постоянное хранилище** (volume/volume для БД):

5. **Порт указывать не нужно** — бот работает через long polling.

6. Нажмите **Собрать/Деплой** и смотрите логи сборки. Успешный старт

   [start] Запускаю бота…

     Polling запущен.
   ```

### Частые проблемы с хостингом

| Симптом | Причина и решение |
|---------|-------------------|
| `СЕТЬ: нет доступа к api.telegram.org — ConnectTimeout` | **Сеть хостинга блокирует Telegram.** Бот останется жив и будет повторять попытки, но без прокси работать не будет. Нужен `TELEGRAM_PROXY=socks5://user:pass@host:1080` либо зарубежный хостинг |
| Бот падает и перезапускается каждые ~30 секунд | Проверьте `Повтор через N с` в логах: скорее всего недоступен `api.telegram.org`. Укажите `TELEGRAM_PROXY` |
| `Порт 8080 внутри контейнера НЕ отвечает` | Панель ждёт HTTP на порту из `PORT`. Бот поднимает `/health`; убедитесь, что `PORT` задан в переменных окружения |
| `ОШИБКА: Telegram отклонил токен (401 Unauthorized)` | Неверный `BOT_TOKEN`. Проверьте значение в панели, лишние пробелы и кавычки недопустимы |
| `BOT_TOKEN не задан` | Не задана переменная окружения в панели |
| `BOT_TOKEN присутствует в переменных окружения, но не был прочитан` | Не установлен `pydantic-settings`. Выполните `pip install -r requirements.txt` |
| `chown: appuser: No such file or user` | Порядок шагов в Dockerfile нарушен: `useradd` обязан идти **до** `chown` |
| `permission denied` для `/app/data` | Volume смонтирован с правами root. Выполните на хосте `chown -R 10001:10001 <путь-к-volume>` либо добавьте `user: "0:0"` в сервис compose |
| Каталог доступен только для чтения | read-only mount — уберите флаг `:ro` у тома |
| `Conflict: terminated by other getUpdates` | Запущено два контейнера с одним токеном — остановите лишний |
| Пустой лог | Проверьте, что в панели указан `CMD: python docker-entrypoint.py` либо Dockerfile в корне |
| Картинки без русского текста | В образе должны быть шрифты; проверьте строку `Шрифты:` в логах |

> **Проверка состояния без доступа к логам:** бот отдаёт HTTP на порту из
> переменной `PORT` (по умолчанию 8080), путь `/health`:
>
> ```json
> {"status": "ok", "bot": "running", "telegram": "connected"}
> ```
>
> Значение `telegram` показывает состояние связи с Telegram: `connected` —
> всё работает, `error: <класс ошибки>` — идут повторные попытки.
> Это надёжнее, чем судить о работоспособности по зелёному контейнеру.

## 🌍 Прокси для Telegram: как подключить

Если сеть хостинга не пускает к `api.telegram.org`, укажите socks5-прокси
через переменную окружения `TELEGRAM_PROXY`:

```
TELEGRAM_PROXY=socks5://логин:пароль@хост:порт
```

| Ситуация | Что писать |
|----------|------------|
| Прокси с логином и паролем | `socks5://user:pass@1.2.3.4:1080` |
| Прокси без авторизации | `socks5://1.2.3.4:1080` |
| Пароль содержит `@` или `:` | Замените их на `%40` и `%3A` соответственно |
| Указываете HTTP-прокси | `http://user:pass@1.2.3.4:8080` |

После добавления переменной нужен **перезапуск (передеплой)** приложения.

### Проверить прокси локально, до деплоя

В проекте есть готовый скрипт — не нужно вписывать код в командную строку:

```powershell
python check_proxy.py socks5://логин:пароль@хост:порт
```

Схему можно опустить — скрипт подставит `socks5://` сам:

```powershell
python check_proxy.py 1.2.3.4:1080
```

Вывод будет понятным, логин и пароль в нём маскируются:

```
============================================================
Проверка прокси: socks5://***:***@1.2.3.4:1080
============================================================
Запрос к https://api.telegram.org/bot0:AA/getMe …

ПРОКСИ РАБОТАЕТ
Telegram ответил 401 на заведомо неверный токен — канал исправен.
Можно указывать в переменных окружения:
  TELEGRAM_PROXY=socks5://***:***@1.2.3.4:1080
```

Скрипт также запускается **внутри контейнера** — это полезно, когда сомневаетесь,
работает ли прокси именно из сети хостинга:

```bash
docker exec -it chat-constructor-bot python check_proxy.py socks5://user:pass@host:1080
```

Код `401` — успех: значит прокси дошёл до Telegram (токен в проверке заведомо
неверный). Остальные результаты:

| Ответ | Значение |
|-------|----------|
| `401` | Прокси исправен, можно использовать |
| `порт занят НЕ прокси` | Перепутан порт или адрес |
| `прокси не отвечает` | Неверный адрес, порт или прокси выключен |
| `неверный логин или пароль` | Нет авторизации или она отклонена |

> Перед деплоем всегда прогоняйте `python check_docker.py` — валидатор проверяет
> в том числе, что пользователь создаётся раньше `chown` (регрессия, из-за
> которой сборка падала на некоторых хостингах).

## 👑 Настройка ADMIN_IDS

Администраторы получают доступ к командам `/admin`, `/stats`, `/users`, `/broadcast`.

**Как узнать свой Telegram ID:**

1. Откройте [@userinfobot](https://t.me/userinfobot) и нажмите Start
2. Бот покажет ваш ID, например `712345678`
3. Впишите его в `.env`:

```ini
ADMIN_IDS=712345678
```

Несколько администраторов — через запятую:

```ini
ADMIN_IDS=712345678,987654321,555000111
```

> ⚠️ Список применяется **только при перезапуске бота**.

**Что доступно администратору:**

| Раздел | Возможности |
|--------|-------------|
| 📊 Статистика | пользователи, новые сегодня, активные за 24 ч / 7 дней, переписки, черновики, изображения, AI-генерации, топ пользователей, статистика по стилям |
| 👥 Пользователи | список с пагинацией: ID, имя, Premium, счётчики |
| 📢 Рассылка | текст + **обязательное подтверждение** перед отправкой, прогресс и итоги |
| ⚙️ Лимиты | изменение любого лимита без правки кода, сброс к значениям из `.env` |

**Ограничения админки:**
- Рассылка всегда требует подтверждения — отправка не начнётся случайно
- Пауза между сообщениями (0.05 с) защищает от лимитов Telegram
- Заблокированные пользователи учитываются как «не доставлено»
- Действия админов пишутся в лог

## 🤖 Подключение OpenRouter (AI)

Функция **✨ Создать сценарий** необязательна. Без ключа бот работает полностью,
просто кнопка объясняет, что AI недоступен.

**Шаги:**

1. Зарегистрируйтесь на https://openrouter.ai/
2. Пополните баланс или используйте бесплатные модели
3. Создайте API-ключ в разделе https://openrouter.ai/keys
4. Впишите ключ в `.env`:

```ini
OPENROUTER_API_KEY=sk-or-v1-ваш_ключ_сюда
OPENROUTER_MODEL=openai/gpt-4o-mini
```

**Популярные модели:**

| Модель | Комментарий |
|--------|-------------|
| `openai/gpt-4o-mini` | недорогая, быстрая (рекомендуется) |
| `anthropic/claude-3.5-sonnet` | качественный креатив |
| `google/gemini-flash-1.5` | быстрая и дешёвая |
| `meta-llama/llama-3.1-8b-instruct` | бесплатная |
| `mistralai/mistral-small` | бюджетная |

**Как это работает:**

1. Пользователь описывает сценарий своими словами
2. Бот отправляет запрос в OpenRouter с жёстким системным промптом
3. Модель возвращает строгий JSON: участники + сообщения
4. Бот валидирует ответ и создаёт переписку в редакторе
5. Пользователь может отредактировать результат

**Безопасность AI-сценариев:**

Системный промпт прямо запрещает модели создавать тексты, которые можно
выдать за реальную переписку, документы, банковские уведомления или
доказательства. Готовый сценарий попадает в редактор с пометкой о том,
что он вымышленный.

**Проверка ключа:**

```bash
python check.py
```

В отчёте будет: `AI: включён (модель openai/gpt-4o-mini)` или
`AI: отключён (нет ключа)`.

## ❗ Решение проблем

### `BOT_TOKEN не задан`

```text
RuntimeError: BOT_TOKEN не задан. Скопируйте .env.example в .env...
```

Создайте `.env` и впишите токен. Проверьте, что файл называется именно
`.env`, а не `.env.txt`.

### Токен невалидный

```text
TelegramUnauthorizedError
```

Получите новый токен через [@BotFather](https://t.me/BotFather) → `/token`.

### `Conflict: terminated by other getUpdates request`

Бот уже запущен в другом процессе. Остановите все копии:

```bash
# Windows
taskkill /F /IM python.exe
# Linux
pkill -f "bot.main"
```

### Русский текст — квадраты или пустые рамки

Шрифт без кириллицы. Выполните `python check.py` и посмотрите строку `Шрифты:`.
Если `text_font` = `встроенный Pillow`, положите шрифт в `fonts/` —
см. [fonts/README.txt](fonts/README.txt).

### Emoji не отображаются

Не найден emoji-шрифт. Установите `NotoColorEmoji.ttf` в `fonts/`
или системный пакет `sudo apt install -y fonts-noto-color-emoji`.
На Windows `seguiemj.ttf` обычно уже есть в `C:\Windows\Fonts`.

### `ModuleNotFoundError: No module named 'bot'`

Запускайте из корня проекта, где лежит папка `bot`: `python -m bot.main`.
Проверьте, что активировано виртуальное окружение.

### Изображение не отправляется

Обычно превышен лимит Telegram (фото до 10 МБ). Уменьшите ширину:
`RENDER_WIDTH=800`.

### «Достигнут лимит»

Сбросьте лимиты из админки (`/admin` → ⚙️ Лимиты) или измените `.env`.
События старше 30 дней чистятся автоматически при старте.

### `sqlite3.OperationalError: database is locked`

Два процесса используют одну базу. Остановите лишние копии бота.

## ✅ Что реализовано

**Ядро**
- Полный цикл: создание → редактирование → предпросмотр → генерация → сохранение → повторное открытие → редактирование → новая генерация
- 5 стилей интерфейса на общем движке (Telegram — основной и самый проработанный)
- Автосохранение после каждого действия + восстановление черновика
- Двухпроходный рендерер с автоматической высотой

**Редактор**
- Текст, emoji, фото из Telegram, голосовые, файлы, стикеры
- Ответы, пересылки, реакции, галочки, время, разделители дат, системные сообщения
- Правка текста, времени, автора, типа, реакции
- Перемещение вверх/вниз, удаление, очистка

**Контент**
- 10 шаблонов вымышленных переписок
- AI-генерация сценариев (OpenRouter) с защитным промптом
- Корректное отключение AI при отсутствии ключа

**Данные**
- SQLAlchemy 2.0 + SQLite, 5 таблиц
- Репозитории: пользователи, переписки, события, статистика, рассылки
- JSON-конфигурация переписки целиком в одной колонке

**Администрирование**
- `/admin`, `/stats`, `/users`, `/broadcast` (с подтверждением)
- Изменение лимитов без правки кода
- Рассылка с прогрессом и учётом ошибок

**Защита**
- Лимиты генераций и AI-запросов (в SQLite, переживают перезапуск)
- Антиспам по действиям в минуту
- Блокировка пользователей
- Пометка `FICTIONAL CHAT` — по желанию, включается в настройках переписки
- Токены и ключи не попадают в логи

**UX**
- `edit_message_text` вместо новых сообщений
- «⬅️ Назад» на каждом экране
- `/cancel` в любой момент
- Понятные состояния: где находишься, что редактируешь, что будет дальше
- Обработка неизвестных кнопок и команд

Проект подготовлен к дальнейшему развитию:

| Возможность | Что уже есть | Что нужно добавить |

| **Другие языки** | Тексты в `keyboards/texts.py`, локализация в одном месте | Добавить `i18n`-словарь и `gettext`-обёртки |

**Архитектурные точки расширения:**

## 📄 Ответственность

Проект предоставляется «как есть». Пользователь несёт ответственность
за содержание создаваемых переписок и обязуется не использовать бота для:

- подделки документов, удостоверений и официальных писем;
- создания фальшивых банковских и государственных уведомлений;
- выдачи вымышленных переписок как доказательств в суде, спорах или при
  спорах с третьими лицами;
- фишинга, кражи аккаунтов и любых мошеннических схем.

При желании на изображение можно добавить пометку
`FICTIONAL CHAT` / `ВЫМЫШЛЕННАЯ ПЕРЕПИСКА` — она включается
в настройках переписки (⚙️ Настройки → «Пометка «вымышленная переписка»»).
